# 사용자 관리 테스트 데이터 설계

## 목적

이미 생성된 Oracle 사용자 관리 테이블에서 원본 데이터를 대상으로 대상 테이블의 삽입과 갱신을 함께 검증한다. 모든 값은 가공된 테스트 데이터이며 실제 사용자 정보나 연결 정보는 포함하지 않는다.

## 산출물

- `data/user-management-test-data.sql`: 원본 세 테이블과 대상 세 테이블의 초기 시드 데이터
- `data/user-management-merge-test.sql`: 원본에서 대상에 적용하는 세 개의 Oracle `MERGE` 문

## 데이터 패턴

각 테이블에서 원본은 세 행을 가진다.

| 구분 | 식별자 | 대상 초기 상태 | 기대 결과 |
| --- | --- | --- | --- |
| 변경 대상 | 사용자 1001, 주소 2001, 내보내기 3001 | 같은 키의 오래된 값이 존재 | `MERGE`가 최신 원본 값으로 갱신 |
| 신규 대상 A | 사용자 1002, 주소 2002, 내보내기 3002 | 행 없음 | `MERGE`가 삽입 |
| 신규 대상 B | 사용자 1003, 주소 2003, 내보내기 3003 | 행 없음 | `MERGE`가 삽입 |

대상의 변경 대상 행은 로그인 ID, 사용자 이름, 이메일, 상태, 주소 도시와 우편번호 등에서 원본과 다른 값으로 시작한다. 병합은 사용자 ID, 주소 ID, 내보내기 ID를 각각 매칭 키로 사용한다. 주소의 `USER_ID`와 내보내기의 사용자·주소 ID는 부모·자식 참조가 유효하도록 같은 명시적 식별자를 사용한다.

## 실행과 검증

1. 실제 Oracle XE 스키마에서 시드 스크립트를 실행한다.
2. 대상 초기 상태를 확인해 각 테이블에 하나의 변경 후보와 두 개의 부재 키가 있는지 확인한다.
3. 병합 스크립트를 실행한다.
4. 각 대상 테이블이 세 행을 가지며, 1001/2001/3001 행은 원본의 최신 값이고 1002·1003/2002·2003/3002·3003 행은 삽입됐는지 확인한다.

이 작업은 `DELETE`, `TRUNCATE`, `DROP`을 사용하지 않는다. 이미 존재하는 시드 키가 있으면 실행을 중단해 기존 테스트 결과를 덮어쓰지 않는다.
