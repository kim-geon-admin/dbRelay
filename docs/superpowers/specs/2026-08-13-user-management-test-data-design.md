# 사용자 관리 테스트 테이블 DDL 설계

## 목적

DB Relay의 Oracle 이관 흐름을 수동으로 검증할 수 있도록 사용자 관리 도메인의 원본 및 대상 테이블 구조를 제공한다. 이 문서는 테이블 DDL만 다루며, 샘플 데이터 DML은 후속 작업으로 분리한다.

## 산출물

`data/user-management-tables.sql` 파일 하나를 추가한다. 스크립트는 기존 객체를 삭제하거나 데이터를 삽입하지 않고 Oracle `CREATE TABLE` 문만 포함한다.

## 테이블 구조

원본과 대상은 같은 컬럼 및 제약 구조를 사용하고, 접두사만 구분한다.

| 원본 | 대상 | 역할 |
| --- | --- | --- |
| `SRC_USERS` | `TGT_USERS` | 사용자 기본 정보를 보관하는 부모 테이블 |
| `SRC_USER_ADDRESSES` | `TGT_USER_ADDRESSES` | 사용자 주소를 보관하는 자식 테이블 |
| `SRC_USER_CONTACT_EXPORT` | `TGT_USER_CONTACT_EXPORT` | 앞의 두 테이블에서 선택한 사용자·주소 정보를 보관하는 이관용 평면 테이블 |

`*_USERS`는 `USER_ID` 기본 키, 로그인 ID와 이메일의 고유성, 사용자 상태 검증을 둔다. `*_USER_ADDRESSES`는 `ADDRESS_ID` 기본 키와 `USER_ID` 외래 키로 각 사용자에 연결한다. `*_USER_CONTACT_EXPORT`는 사용자 ID와 주소 ID, 로그인 ID, 이메일, 주소 유형 및 주소 일부를 포함해 부모·자식 테이블의 컬럼 일부를 재사용한다.

모든 테이블은 8개 이하의 컬럼을 가진다. 식별자 컬럼은 `GENERATED BY DEFAULT AS IDENTITY`로 생성해 명시적 키 이관도 가능하게 한다.

## 제약과 실행 특성

- 외래 키는 `SRC_USER_ADDRESSES.USER_ID → SRC_USERS.USER_ID` 및 대상의 동등한 관계에만 둔다.
- 스크립트는 참조 순서에 맞춰 부모, 자식, 평면 테이블 순서로 생성한다.
- 이후 데이터 준비 단계에서만 `INSERT` 문을 별도 SQL 파일로 추가한다.
- 기존 테이블이 있으면 Oracle의 기본 동작으로 오류를 반환한다. 테스트 계정의 정리나 재생성은 이 스크립트 범위가 아니다.

## 검증

DDL은 정적 검사로 테이블 여섯 개, 각 테이블의 컬럼 수, 원본/대상 구조 동등성, 두 외래 키 정의, 그리고 DML·파괴적 DDL의 부재를 확인한다. 애플리케이션 소스는 바꾸지 않으므로 전체 패키지 검증은 요구하지 않는다.
