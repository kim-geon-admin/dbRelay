# DB Relay 설계 문서

**상태:** 사용자 검토 대기  
**작성일:** 2026-07-31  
**플랫폼:** Windows 데스크톱 — Tauri 2, Rust, React/TypeScript

## 목표

여러 데이터베이스 연결 설정과 재사용 가능한 이관 플로우를 로컬에서 관리하고, 한 데이터베이스의 조회 결과를 다른 데이터베이스에 순차적으로 upsert한다. 첫 커넥터는 Oracle이며, 후속 DB를 추가할 때 실행 엔진이나 UI를 바꾸지 않도록 한다.

이 설계는 [하네스 엔지니어링](https://openai.com/ko-KR/index/harness-engineering/)의 원칙을 따른다. 즉, 짧은 작업 지도, 버전 관리되는 설계·실행 문서, 명시적인 계층 경계, 자동화된 구조/행동 검증을 제품의 일부로 둔다.

## 범위와 핵심 결정

- Windows용 Tauri 2 애플리케이션을 Rust 코어와 React/TypeScript UI로 구현한다.
- DB 연결 설정은 여러 개 등록할 수 있으며, 실행 시 원본(조회)과 대상(upsert)을 각각 선택한다.
- 플로우는 이름, 원본/대상 DB 설정 참조, 정렬된 쿼리 단계, 트랜잭션 정책을 저장하고 재사용·복제·수정할 수 있다.
- 업서트 입력은 조회 결과 컬럼 별칭과 대상 SQL의 `:바인드_변수`를 대소문자 구분 없이 자동 매핑한다.
- Oracle을 첫 구현체로 제공하고, DB 차이점은 `DatabaseConnector` 계약 뒤에 둔다.
- UI는 `DESIGN-claude.md`의 크림 캔버스, 코럴 CTA, 어두운 실행 로그, 세리프 제목을 적용한다.

## 사용자 경험

### 주요 화면

1. **실행** — 저장된 플로우를 선택해 DB 연결 상태, 트랜잭션 정책, 순차 쿼리 목록, 실행 로그를 확인하고 실행한다.
2. **쿼리 시퀀스** — 플로우별 쿼리 단계의 추가, 삭제, 순서 변경, 조회 SQL과 upsert SQL 편집, 바인드 변수 검증을 제공한다.
3. **DB 설정** — 연결 이름, DB 종류, 호스트/포트/서비스, 사용자명, 비밀 정보를 등록하고 연결을 시험한다.
4. **실행 이력** — 플로우 버전, 시작/종료 시각, 단계별 상태, 처리 건수, 오류 코드, 사용자가 선택한 복구 작업을 조회한다.

### 저장된 플로우

플로우는 연결 비밀번호를 복제하지 않는다. 다음 정보만 저장한다.

- 표시 이름과 설명
- 원본 DB 설정 ID, 대상 DB 설정 ID
- 순서가 있는 `QueryStep` 목록
- 정책: `all_or_nothing` 또는 `commit_successes`
- 생성/수정 시각과 플로우 버전

플로우에서 참조하던 DB 설정이 삭제되거나 비활성화되면 실행을 차단하고 해당 설정을 다시 선택하도록 표시한다.

## 아키텍처

```text
React UI
  ↓ (좁은 Tauri Command API)
Application Services
  ├── FlowService / SettingsService / HistoryService
  └── MigrationRunner
        ├── MappingValidator
        ├── RecoveryController
        └── ConnectorRegistry
              └── DatabaseConnector
                    └── OracleConnector (초기 구현)
  ↓
SQLite Metadata Repository + Windows Credential Manager
```

### 계층 책임

| 계층 | 책임 | 의존 가능 대상 |
|---|---|---|
| UI | 폼, 상태 표시, 복구 선택, 사용자 알림 | Tauri command DTO만 |
| Application | 유스케이스 조정, 상태 전이, 감사 이력 | 도메인 계약, repository, connector |
| Domain | 플로우, 쿼리 단계, 정책, 실행 결과, 검증 규칙 | 표준 라이브러리만 |
| Infrastructure | SQLite, Windows Credential Manager, Oracle 드라이버 | 도메인/application의 포트 구현 |
| Connector | DB 연결, 조회, 바인드 실행, 트랜잭션 | `DatabaseConnector` 계약 |

UI는 DB 드라이버나 SQL 연결 문자열에 직접 접근하지 않는다. Rust command는 필요한 DTO만 노출하며, 비밀 정보는 반환하지 않는다.

### 확장 계약

`DatabaseConnector`는 다음 역할을 제공한다.

- 연결 설정 유효성 검사와 연결 시험
- 조회 SQL 실행 후 열 이름과 행 값을 표준 `Row`로 반환
- 대상 SQL에 명명 바인드 값을 적용하여 일괄 실행
- 대상 트랜잭션의 시작, 커밋, 롤백
- DB별 오류를 공통 `ConnectorError`로 변환하되 원본 코드·메시지는 보존

Oracle 구현은 Oracle용 `MERGE` SQL을 그대로 실행한다. PostgreSQL, SQL Server 등의 추가 구현은 이 계약을 구현하고 설정 화면의 DB 종류 목록에 등록한다.

## 쿼리와 매핑

각 `QueryStep`은 조회 SQL과 대상 upsert SQL을 가진다. 대상 SQL의 `:NAME` 파라미터는 조회 결과의 `NAME` 열 별칭에 자동 연결된다.

- 매핑은 대소문자를 무시하고 정확한 이름으로 한다.
- 대상 파라미터가 원본 열에 없으면 실행 전 오류로 막는다.
- 중복된 정규화 열 이름, 이름 없는 열, 지원하지 않는 바인드 문법도 실행 전 오류다.
- 원본의 추가 열은 무시한다.
- SQL 텍스트, 매핑 검증 결과, 플로우 버전을 실행 이력에 기록한다. 바인드 값과 조회 행 데이터는 기록하지 않는다.

## 트랜잭션과 실패 복구

### 전체 롤백 (`all_or_nothing`)

대상 DB에서 하나의 트랜잭션으로 모든 단계를 실행한다. 어느 단계든 실패하면 전체 대상 트랜잭션을 롤백하고 실행을 종료한다. 어떤 단계도 커밋되지 않는다.

### 성공분 커밋 (`commit_successes`)

각 쿼리 단계는 독립된 대상 트랜잭션이다. 성공한 단계는 즉시 커밋한다. 실패한 단계만 롤백하고 러너는 `AwaitingRecovery` 상태로 일시 중지한다. 이 상태에서는 다음 대화형 선택지를 정확히 하나 선택해야 한다.

1. **수정 후 재진행** — 실패한 단계의 조회/대상 SQL을 UI에서 편집한다. 저장 전 바인드 변수와 연결을 다시 검증하고, 성공하면 실패한 단계만 새로 조회하여 재실행한다. 편집된 단계와 재시도 횟수는 이력에 남긴다.
2. **이 쿼리 건너뛰고 계속** — 실패한 단계를 `SkippedByUser`로 기록하고 바로 다음 단계를 실행한다. 이 선택은 되돌릴 수 없으며, 처리하지 않은 데이터가 남을 수 있음을 UI가 명시한다.
3. **실행 중지** — 남은 단계를 실행하지 않고 실행을 `StoppedByUser`로 종료한다. 이미 성공한 단계의 커밋은 유지한다.

실패 모달은 쿼리 순서, 플로우 이름, Oracle 오류 코드와 원문 메시지, 이미 커밋된 단계 수를 표시한다. 원문 오류에서 비밀 정보가 발견되면 마스킹한다.

## 실행 상태

`Draft → Validating → Running(step n) → AwaitingRecovery → Running(step n+1) → Completed`가 정상 상태 전이다. 실패 후 사용자가 중지하면 `StoppedByUser`, 전체 롤백 정책의 오류면 `RolledBack`, 취소 불가능한 내부 오류면 `Failed`로 종료한다. 종료 상태와 각 단계의 `Succeeded`, `Failed`, `SkippedByUser`, `NotRun`을 이력에 보존한다.

## 보안과 데이터 보호

- 앱 메타데이터와 플로우 정의는 앱 전용 로컬 SQLite에 저장한다.
- 비밀번호·토큰은 Windows Credential Manager에 별도 저장하고 SQLite에는 credential reference만 둔다.
- 연결 문자열의 비밀 부분, 비밀번호, 토큰, 바인드 값, 조회 행은 로그/이력/UI 오류 복사본에 남기지 않는다.
- 비밀이 포함될 가능성이 있는 드라이버 오류는 표시와 저장 전에 마스킹한다.
- SQL 편집·실행은 로컬 사용자의 명시적 조작으로만 수행한다. 자동 스케줄 실행, 공유, 원격 전송은 첫 릴리스 범위에서 제외한다.

## 오류와 알림

성공 시에는 플로우명, 완료 단계 수, 처리 건수, 소요 시간을 토스트와 이력으로 제공한다. 실패 시에는 단계명, 단계 번호, DB 종류, 원본 오류 코드/메시지, 트랜잭션 결과를 명확히 표시한다. 연결 실패, SQL 검증 실패, 매핑 실패, 트랜잭션 실패는 사용자 친화적 제목과 기술 세부 정보 펼침 영역을 함께 제공한다.

## 하네스 엔지니어링 운영물

구현 시작 시 다음 문서를 저장소에 둔다.

```text
AGENTS.md                         # 100줄 이내 작업 지도와 필수 검증 명령
ARCHITECTURE.md                   # 계층·의존 방향·공개 경계
docs/
  product-specs/                  # 사용자 기능의 결정 기록
  design-docs/                    # DB 커넥터와 데이터 모델 결정
  exec-plans/active/              # 진행 중인 작업 계획
  exec-plans/completed/           # 완료된 계획과 결과
  generated/                      # 생성 가능한 스키마/계약 문서
  superpowers/specs/              # 승인된 설계 문서
```

기계적으로 강제할 규칙은 다음과 같다.

- domain은 infrastructure, Tauri, React에 의존하지 않는다.
- UI는 connector 또는 credential 구현을 import하지 않는다.
- 새 DB는 `DatabaseConnector` 구현과 등록 외에 `MigrationRunner` 변경을 요구하지 않는다.
- 모든 새 상태 전이, 매핑 규칙, 오류 마스킹에는 단위 테스트가 있다.
- 커밋 전 포맷, lint, Rust/TypeScript 테스트, 구조 테스트를 모두 통과해야 한다.

## 검증 전략

| 수준 | 검증 대상 |
|---|---|
| Rust 단위 테스트 | 매핑 검증, 상태 전이, 전체 롤백/성공분 커밋 결정, 복구 선택, 오류 마스킹 |
| React 단위 테스트 | 설정 폼 검증, 실패 모달의 세 선택지, 실행 상태 렌더링 |
| 계약 테스트 | `DatabaseConnector`의 연결·조회·바인드·트랜잭션·오류 변환 동작 |
| 통합 테스트 | 격리된 Oracle 테스트 인스턴스에서 `MERGE`, 롤백, 단계별 커밋, 재시도/건너뛰기/중지 |
| 구조 테스트 | 허용되지 않은 계층 import와 비밀 정보 DTO 노출 차단 |

## 첫 릴리스 제외 범위

- 자동 스케줄, 백그라운드 예약 실행, 다중 사용자 공유
- 대용량 데이터의 병렬 실행·분산 재시도
- Oracle 외 실제 커넥터 구현
- SQL 자동 생성, 데이터 변환 스크립트, 스키마 마이그레이션

## 수용 기준

1. 사용자는 두 개의 저장된 Oracle 설정을 원본과 대상으로 선택해 플로우를 실행할 수 있다.
2. 사용자는 플로우에 여러 쿼리 단계를 저장하고 순서대로 실행할 수 있다.
3. 올바른 조회 열 별칭은 대상 SQL의 명명 바인드 변수에 자동 전달되며, 누락은 실행 전에 설명과 함께 차단된다.
4. 전체 롤백 정책의 어떤 오류도 대상 DB에 변경을 남기지 않는다.
5. 성공분 커밋 정책에서 오류가 나면 이미 성공한 단계는 유지되고, 사용자는 수정 후 재진행·건너뛰기·중지 중 하나를 선택할 수 있다.
6. 실행 이력은 각 단계의 결과와 선택한 복구 작업을 보이되 비밀/행 데이터는 노출하지 않는다.
7. 새 커넥터 구현을 추가할 때 UI 또는 이관 러너를 변경하지 않는다.
